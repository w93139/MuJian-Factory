# macOS 桌面一键启动幕间

## 使用

双击桌面的「启动幕间.command」。真正的入口文件保存在 MuJian 根目录，桌面只有指向它的符号链接。

启动器检查当前 MuJian 的后端 8000 与新版前端 3110：

- 已运行：检查就绪后直接打开默认浏览器。
- 未运行：通过当前登录用户的 macOS 后台服务启动，再等待网站可用。
- 失败：启动窗口显示原因、相关日志尾部与日志路径；按回车结束。
- 端口被其他程序或另一个项目占用：报告占用情况，不结束那个程序。

页面地址为 `http://127.0.0.1:3110/`，数字人配音入口为 `/pipelines/digital-human`，在「生成配置」中查看配音模型。前端通过同源代理连接 `http://127.0.0.1:8000`。只监听本机。

启动器创建的前端固定连接 8000。若此前曾手动在同一目录的 3110 端口启动过连接其他测试后端的实例，应先停止那个手动实例，再使用桌面入口；目录和模型目录相同不能完全区分这种手动配置。

后台服务独立于启动窗口，关闭窗口后继续运行。没有创建开机登录项；电脑重启或退出登录后，再双击一次即可。启动器不执行 Git 拉取、自动安装、模型生成、数据迁移或素材清理。

## 文件位置

- 根目录 `启动幕间.command`：Finder 双击入口，项目移动时通过自身位置定位。
- `scripts/local_launcher.py`：运行环境检查、端口归属检查、后台服务启动和诊断。
- `.local-runtime/launcher/launcher.log`：启动日志。
- `.local-runtime/launcher/backend.log`、`frontend.log`：前后端日志。
- 同一运行目录的 `.plist`：本机绝对路径与后台服务定义，不保存 API Key，不提交 Git。

启动器支持 Homebrew、PATH 和 `~/.nvm/versions/node/` 中的 Node.js 20.9+。后端复用 `backend/.venv/bin/python`；前端使用已安装的 `frontend/node_modules`。依赖缺失会提示修复命令。第一次启动的页面编译可能需要几十秒。

查看失败原因时，优先看启动窗口最后的报错，再看上述日志。macOS 如果明确阻止后台程序访问项目目录，应按系统提示处理对应权限；启动器不会自动修改权限。

## 命令行

从 MuJian 根目录执行：

```sh
./启动幕间.command             # 启动并打开网页
./启动幕间.command --no-open   # 启动、检查，不打开网页
./启动幕间.command --stop      # 仅停止这个启动器创建的后台服务
```

停止命令不处理手动启动的进程、不停止其他项目。若要移动项目，应先停止旧位置的后台服务，再在新位置启动，并更新桌面快捷链接。

其他电脑从 GitHub 下载项目后，先按 README 准备依赖和私有配置，再双击根目录入口；也可以在 Finder 为它创建桌面替身。本次电脑上的桌面符号链接不作为源码上传。
