| 标签 | 提交 | 含义 |

| archive/original-2026-10-10 | 0ab8dff | 改版前原项目代码 |

本次交付属于待用户验收版本；没有创建 accepted 标签，也不会据自动测试结果停用旧版。交付提交以 Git main 和提交记录为准，标签与代码正常推送 origin，不强推、不改写历史。

## 后续每次更新

1. 检查工作区、提交和来源；明确保存需要保留的未提交工作。
2. 修改前在已提交版本创建一个唯一的 `checkpoint/用途-日期` 标签。
3. 在 main 完成限定范围修改、必要测试、提交和同步。
4. 用户明确验收通过后，为实际验收提交创建 `accepted/用途-日期` 标签。新版本未验收前保留旧入口。

标签是固定快照，不自动追随 main；不要移动已发布标签。相同日期多次更新可在名称中增加序号。

## 需要回看或恢复时

优先创建独立目录查看旧代码，不直接重置当前仓库。由代理检查运行依赖和数据格式后执行，例如：

```bash
cd /Users/syk/Desktop/MuJian
git worktree add --detach .local-artifacts/recovery-original archive/original-2026-10-10
```

这会取回完整前后端源码，但不会自动复制密钥、项目数据和媒体。运行时使用独立端口与隔离的数据副本；不要让两个版本同时写同一份真实数据。正式回退采用保留历史的提交流程，不对 main 强推或重写已发布历史。

`旧版完整备份/` 仍保留原 Git、配置、运行数据和媒体，`新前端设计版/` 仍独立保留选定设计。这两个目录不随本次瘦身改写。Git 保存代码；私有配置、真实项目和媒体依赖本地备份，两者不能互相替代。
